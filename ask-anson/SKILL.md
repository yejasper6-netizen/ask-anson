# Ask Anson

把用户当前的问题交给合适的思考方法。用户无需记方法名、编号或手填模板。共十八个入口，包含思考方法及情境判断框架。首批十二种方法的场景整理参考卡兹克公开分享，六个补充入口分别依据其作者或官方资料独立编写。本 Skill 的贡献在于场景区分、选法规则和 Codex 执行适配；具体来源见 [来源](references/source.md)，平时无需加载完整来源记录。

## 调用与执行

1. 先读本轮问题、相关材料和已确认的约束；从可见对话识别上轮的目标、方法、完成情况及未解决的关键问题，不虚构不可见的历史。用户只调用 Skill 而没有具体问题时，简短询问“你现在遇到的具体问题是什么？”；不先发方法菜单。
2. 按下节优先级决定沿用、切换或先澄清。需要重新选法时，判断任务处于了解、选择、计划、执行受阻或事后复盘哪个阶段，再找主要阻碍，依据方法表及相近方法分界选择。默认只选一种；确实需要两种时，说明先后关系并只读取当前阶段需要的文件。
3. 用一句短话说明当前选法；多轮时点明是沿用还是切换，并把本轮要求、具体条件和主要卡点连接起来。不能仅说“这个问题很复杂”或复述方法名。随后直接完成本轮交付，不增加一次选法确认。用户说“只推荐”时止于推荐；说“只要提示词”时读取所选指令，给可复制且已填入其情况的提示词，不在当前回答执行那段提示词。
4. 只读取所选方法的参考文件。直接使用上下文填充任务、目标、材料和限制；需要且允许追问时，每轮只问一个关键问题；不追问时按下节第5项处理。已有可查材料先查材料，信息足够就给结果。
5. 输出应回答用户的问题。篇幅跟随任务需要，不因模板而写万字报告，也不把未填写的占位符交回用户。保留方法要求的必要互动；用户明确要求单轮回答时，列明假设后给条件性结论。

## 多轮路由优先级

以下顺序用于消解冲突，方法的编号和数量不代表优先级：

1. **本轮交付与硬约束。** 先识别这次要建议、解释、核查、实验方案还是复盘，以及只推荐、只给提示词、不追问、不设计实验等限制。最新明确要求优先；此前已确认且未撤销的目标、事实限定和约束继续有效。方法必须服务于这个交付，不能用“更值得验证”把建议擅自换成实验，也不能用高分抵消硬门槛。
2. **本轮明确指定的方法。** 适合交付时直接遵循，优先于上轮方法和自动选择。如果指定方法会漏掉硬约束或依赖不存在的材料，说明限制，先调整用法或深度；确实不能完成任务时再说明所需调整，不静默改选。
3. **可用的上轮方法优先延续。** 仍是同一任务，且原方法的目的和适用前提仍匹配本轮交付时，沿用并更新结论；不能仅凭模型也能写出所需内容就判为适配。回答上轮问题、补充或纠正事实、修改参数、候选项变少、要求更短或给最终建议，本身都不是切换理由。已完成的比较、解释和提问不从头重复。
4. **交付、阶段或适用前提改变时切换。** 例如比较已结束而本轮明确要实验；选定计划后转查行动前风险；行动已结束转做复盘；估算之后转为核查宣传说法。新证据若使原方法关键前提失效，也重新选法。说明“上轮处理什么、本轮改变了什么、为何新方法能直接完成交付”，保留已确认事实，不能把上轮假设或候选风险升级为事实。
5. **仍有歧义时才澄清。** 两种方法都能完成明确交付时，优先沿用适合的上轮方法；无上轮方法则选最直接的一种。只有不同理解会显著改变任务、且上下文无法消解时，问一个关键问题。单独说“继续”且下一步明确就继续；换了话题却没给具体问题，先询问新问题，不沿用旧话题，不先加载新方法文件或启动01长访谈。用户要求不追问时，明示采用的理解并给有边界的结果，不凭空补造事实。

特别区分：

- **09 → 09：** 双方理由已比较，新事实后要推荐与翻转条件，沿用09完成判断；未知现实反馈可写成判断条件，不自动设计10实验。
- **09 → 10：** 本轮明确改要验证关键假设的实验方案，或现实反馈已成为用户当前要求解决的任务，再切换10。
- **16 → 16：** 多准则筛选后只剩两个方案，原门槛和标准仍适用，继续16；不因“两个”这个词自动切09。本轮明确指定09且可完成交付时，按第2级处理。
- **15 → 15 / 05：** 更新页数、大小或副本数后重算仍用15；本轮检查估算是否足以支撑现有陈述时用05。
- **17 → 10：** 复杂情境中，本轮已限定一个可测试假设并要实验方案，可用10处理该局部任务；不据此宣称整个情境已变简单。

选法取决于主要阻碍，不机械匹配关键词，也不把 17 设为所有任务必经的前置步骤。用户直接问清楚的概念，不先转为问诊。容易混淆的入口按以下区别判断：

- 09 比较两个方向最强的理由；16 比较多个方案或明确的多准则、硬门槛；10 获取能改变决定的一项现实反馈。
- 07 重审基础事实和设计假设；14 寻找限制整个相依流程产出的约束；13 审视已选计划的候选失败路径。
- 03 学习一个成品的结构；18 对照自己已完成行动的计划、事实和偏差，形成下一轮改进。
- 05 检查现有陈述的可信度；15 根据明示假设给数量级与范围，估算不能当作核实事实。
- 10 适合一个能定义和测试的关键假设；17 在因果和约束尚不清楚、连响应方式都待判断时使用。复杂情境可能需要多个可承受失败的探查，不能只验证一个先入为主的解释。

用户指定的方法适合其目标时直接遵循；如果会遗漏硬约束或依赖不存在的材料，简短说明并调整深度或提出更合适的方法。不要自行把一次简单任务升级为正式研究、评分工程或长期访谈。

## 执行质量

- 用事实支撑判断，区分观察、解释、假设与建议。联网研究给可追溯来源；打不开资料就说明缺口，不猜原文内容。学习或类比中的示意例子应清楚标明。
- 本 Skill 内部选择参考提示词已获授权；推荐其他已安装 Skill 不等于调用它们。
- 方法服务于原任务。分析、访谈或设计实验不自动授权改代码、运行业务测试、部署、付费、发布或联系他人；继续遵守该任务已经授权的范围。
- 多视角分析在当前回答内进行，不因“专家会诊”而自动创建子代理。没有实际独立评审，就称为模型内的多视角分析。
- 结尾给与当前问题有关的下一步或仍待解决的关键点；有足够信息就完成，不无限延长采访。
